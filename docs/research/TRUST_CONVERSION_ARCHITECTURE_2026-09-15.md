# Trust / Conversion Architecture Research

更新日: 2026-09-15

## 目的

P02 / P10 の Formal Blind Tournament HOLD を受け、「その会社らしい」から「この会社なら任せられそう」「自分の状況なら相談してよい」へ移るための構造を研究した。P09 は価格透明性の学習対象として維持し、大改修は行っていない。

## Q1: Owner Specificity が高くても Trust が低い理由

Owner Specificity は「誰のための、どんな問題の言い換えか」を評価する軸であり、Trust は「その会社が約束を実行でき、相談後の不利益が予測可能な状態か」を評価する軸である。前者は表現の固有性だけで成立するが、後者には次の接続が必要になる。

`Company Truth → 何をするか → 相談者に何が起きるか → 相談後に何が起きないか → Action`

P02 は「専門語を相談の言葉へ」という翻訳思想と20年／300社以上の支援経験を持つ。しかし前回までは、経験の事実と「状況から相談できる」という行動理由が画面上で離れていた。そのため、会社らしさは高いが、経験が今回の相談にどう使われるか、相談後の不利益がないかを来訪者が補完する必要があった。これは Owner Specificity 1.0000 と Trust 0.0000 が同時に起きる説明になる。

P10 も同様で、「転職したい」がなくてもよいという心理的入口は強い一方、誰が対応するか、クリック後に何が起きるかが未確認のままだと、安心感はコンセプトの共感に留まる。

## 確定した設計仮説

### 1. Proof-to-Process

検証済みの会社固有情報を、CTAから遠い実績バッジで終わらせず、「その経験を使って相談中に何をするか」の一行へ接続する。証拠は増やさず、意味を接続する。

### 2. Permission Before Ask

相談者が決断してから来る前提を外し、「まだ決めなくてよい」「制度名・転職意思が固まっていなくてよい」をCTA前に明示する。これは単なる優しいトーンではなく、相談しても望まない結論へ押されないという心理的安全性の設計である。

### 3. After-Click Certainty

CTA Zoneは `Before CTA / CTA / After CTA` の三段で設計する。押す理由、押した後にすること、決めなくてよい境界を同じ視野に置く。クリック後の具体情報が未確認なら、作り込まずEvidence Slotとして残す。

### 4. Evidence Economy

Trustのためにカード・FAQ・数字を増やさない。原則は「検証済み事実1〜2個＋固有プロセス1行＋行動1つ」。強いScreenの後ろにQuiet Chapterを残し、Screenshot Peak Budget 2〜4を維持する。

### 5. Mobile Action Budget

安心情報を足すほどCTAが下がるため、MobileではCTA Zoneを新しい縦構造として再設計する。390×844でCTAが見え、scrollWidthがviewportを超えないことを必須にし、9幅QAで改行と余白を確認する。

## Prototypeに適用した変更

### P02

- 既存の「20年／300社以上の支援経験」をCTA直前へ移し、相談行動との距離を縮めた。
- 「制度名が分からなくても大丈夫」から「状況を聞く → 必要な制度を整理する」へプロセスを一行で接続した。
- 制度 → 状況 → 相談の主構造、3つの具体例、赤い翻訳矢印は維持した。

### P10

- 既存の「個人の相談は無料」「企業からの紹介手数料で運営」をCTA Zoneの証拠として維持した。
- 「相談では、モヤモヤを聞き、価値観を整理します」を追加し、状態遷移と相談行為を接続した。
- 「転職するかは、相談してから」をCTA直下に置き、相談の前に結論を要求しない境界を明示した。
- 既存のBefore → 整理 → After構造とMobileの縦順は維持し、追加分の余白だけを圧縮した。

### P09からの学び

P09は、400×300mmという実商品サイズと4,158円（税込）を、価格ドライバー・対象・次の判断へ結びつけたため、Business Reviewerが弱くても総合PASSした。数字が強いのではなく、数字が「自分のケースで何が変わるか」を判断させる点が強い。これはP02/P10にも、実績数字を増やすのではなく、既存事実を相談プロセスへ接続する形で移植する。

P02/P10とも正式GateのWin Rateは超えたが、TrustはP02 0.3333、P10 0.3333に留まり、P10のBusiness Owner / Conversion roleも0.3333である。したがって、Formal PASSは得たが、Trust / Conversion研究が完了したとは扱わない。UPPER_MODEL_REVIEW_CANDIDATEとし、次の検証では対応者の実在情報・相談後の境界・守秘／勧誘方針などのCompany Evidenceが必要かを確認する。

## Future Hearing Requirements

今回アプリは作らない。正式版でTrustを成立させるため、次の情報をClient Evidence Slotとして必ず聞けるようにする。

- P02: 代表者名・資格、対応範囲、初回相談後の流れ、回答・連絡の目安、実在する相談例。
- P10: 対応者の氏名・経歴、相談時間と方法、クリック後の予約手順、継続しない場合の扱い、無理な転職誘導をしない方針、守秘・個人情報の扱い。
- 共通: `OWNER_PORTRAIT / OWNER_QUOTE / RESULT_CASE / TESTIMONIAL / VERIFIED_METRIC` は事実が揃うまで表示せず、構造だけ確保する。

## 判断

P02/P10はFormal PASSへ昇格したが、Creative Quality × Trust × Conversionの同時成立はまだ「検証済みの初期段階」である。P09はCOMPETITIVEを維持する。Golden Sample 03とHearing Appには進まず、次はEvidence Slotを埋めたEnriched variantの再比較を推奨する。
